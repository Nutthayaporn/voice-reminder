# คู่มือเชื่อมปฏิทิน Google / Outlook / Apple กับ VORA

VORA อ่านนัดจาก Google Calendar, Microsoft Outlook / Microsoft 365 และปฏิทินบนอุปกรณ์ Apple ได้ ผู้ใช้เลือกปฏิทินที่จะนำเข้าผ่าน **Settings → Calendars** โดยแอปจะไม่เลือกปฏิทินให้อัตโนมัติ

นัดที่เลือกจะแสดงในหน้า **Calendar ของพื้นที่ส่วนตัว** และใช้ตอบคำถามด้วยเสียง เช่น “พรุ่งนี้มีนัดอะไรบ้าง” สรุปตารางประจำวัน หรือหาเวลาว่างได้ รุ่นนี้รองรับ **การอ่านอย่างเดียว** จึงยังแก้ไข ทำเครื่องหมายว่าเสร็จ ลบ แชร์ หรือตั้งการแจ้งเตือนให้นัดภายนอกจาก VORA ไม่ได้

## 1. สิ่งที่ต้องเตรียม

การเชื่อม Google และ Microsoft ต้องเข้าสู่ระบบ VORA ผ่าน Supabase ก่อน บัญชีปฏิทินที่เชื่อมเป็นคนละส่วนกับบัญชีที่ใช้เข้าสู่ระบบ VORA เช่น เข้าสู่ระบบ VORA ด้วยอีเมล แล้วเชื่อมปฏิทิน Google ได้

รุ่นนี้รองรับ Google 1 บัญชี และ Microsoft 1 บัญชีต่อผู้ใช้ VORA หากเชื่อมใหม่จะใช้แทนบัญชีเดิมของผู้ให้บริการนั้น และให้เลือกปฏิทินใหม่ รายการปฏิทินที่เลือกเก็บแยกตามผู้ใช้บนแต่ละอุปกรณ์ ส่วน Apple ใช้งานได้แม้ใช้ VORA แบบเก็บข้อมูลเฉพาะในเครื่อง

ก่อนเปิดใช้งานจริง ต้องทำตามขั้นตอนต่อไปนี้:

1. สร้างตารางและฟังก์ชันฐานข้อมูลตามหัวข้อ 2
2. ลงทะเบียน OAuth app ของ Google และ Microsoft ตามหัวข้อ 4–5
3. ตั้งค่า secrets และ deploy เซิร์ฟเวอร์ตามหัวข้อ 3
4. หากใช้ Apple Calendar ให้ build แอป iOS ใหม่ตามหัวข้อ 6
5. ทดลองเชื่อมบัญชีจริงตามหัวข้อ 9

## 3. ตั้งค่า secrets และ deploy เซิร์ฟเวอร์

ตั้งค่าต่อไปนี้เป็น **Supabase Edge Function secrets** ห้ามใช้ชื่อตัวแปรขึ้นต้นด้วย `EXPO_PUBLIC_` สำหรับค่าเหล่านี้ เพราะค่าประเภทนั้นจะถูกฝังไปกับแอป

| ชื่อ secret | ค่าที่ต้องใส่ |
| --- | --- |
| `GOOGLE_CALENDAR_CLIENT_ID` | Client ID ของ OAuth app แบบ **Web application** ที่สร้างใน Google |
| `GOOGLE_CALENDAR_CLIENT_SECRET` | Client secret ของ Google |
| `MICROSOFT_CALENDAR_CLIENT_ID` | ค่า **Application (client) ID** ของ Microsoft |
| `MICROSOFT_CALENDAR_CLIENT_SECRET` | ค่า **Value** ของ Microsoft client secret ไม่ใช่ Secret ID |
| `CALENDAR_TOKEN_KEY` | คีย์สุ่มขนาด 32 ไบต์ที่เข้ารหัสเป็น Base64 ใช้เข้ารหัส token ด้วย AES-256-GCM ต้องใช้ค่าเดิมต่อเนื่องเมื่อ deploy ใหม่ |
| `CALENDAR_RETURN_URLS` | URL ของแอปที่อนุญาตให้กลับมาได้ คั่นแต่ละรายการด้วยจุลภาค เช่น `https://your-vora.example/,http://localhost:8081/,voicereminder://calendar/callback` |

สร้างค่า `CALENDAR_TOKEN_KEY` ด้วยคำสั่ง:

```sh
openssl rand -base64 32
```

นำผลลัพธ์ไปเก็บในระบบจัดการ secrets โดยตรง หากเปลี่ยนหรือทำคีย์นี้หาย ผู้ใช้ต้องเชื่อมบัญชีปฏิทินเดิมใหม่ อย่าเก็บ credentials ลง git หรือส่งในแชต

เมื่อตั้งค่าครบแล้ว ให้ deploy จากโฟลเดอร์โปรเจกต์:

```sh
supabase functions deploy calendar-api
```

ใช้ค่า `verify_jwt=false` ตามที่กำหนดไว้ใน `supabase/config.toml` เพื่อให้ Google/Microsoft เรียก OAuth callback ได้ ส่วนคำขอ `POST` ทุกคำขอยังตรวจ JWT ของผู้ใช้ VORA ผ่าน `auth.getUser` อยู่ มีเพียง OAuth callback ที่ใช้ได้ครั้งเดียวเท่านั้นที่เข้าถึงได้โดยไม่แนบ JWT

### แยก URL สองประเภทนี้ให้ถูกต้อง

**Callback / Redirect URI ที่ต้องใส่ใน Google และ Microsoft** ใช้ค่าเดียวกันทั้งสองเจ้า:

```text
https://<project-ref>.supabase.co/functions/v1/calendar-api
```

แทน `<project-ref>` ด้วยรหัส Supabase project ของ VORA

ส่วน **`CALENDAR_RETURN_URLS`** คือ URL ปลายทางของแอป VORA หลังเชื่อมบัญชีเสร็จ ลำดับการทำงานคือ:

```text
ผู้ใช้กดเชื่อมใน VORA
→ อนุญาตสิทธิ์ใน Google / Microsoft
→ กลับมายัง callback ของเซิร์ฟเวอร์
→ เซิร์ฟเวอร์บันทึกการเชื่อมต่อ
→ กลับเข้าเว็บหรือแอป VORA ตาม URL ที่อนุญาตไว้
```

URL ต้องตรงกันทุกตัวอักษร รวมถึง `/` ท้าย URL และพอร์ตของเว็บที่ใช้ทดสอบ สำหรับใช้งานจริงให้ใช้ URL แบบ HTTPS ส่วนแอปมือถือให้ใช้ development build สำหรับ native callback และ Apple Calendar ไม่ใช้ Expo Go เป็นตัวทดสอบส่วนนี้

## 4. ตั้งค่า Google Calendar

ใน Google Cloud ให้ดำเนินการดังนี้:

1. เปิดใช้งาน **Google Calendar API**
2. ตั้งค่า **OAuth consent screen** ซึ่งเป็นหน้าที่ผู้ใช้เห็นก่อนอนุญาตให้ VORA เข้าถึงปฏิทิน
3. สร้าง OAuth client โดยเลือกชนิด **Web application**
4. เพิ่ม callback จากหัวข้อ 3 ใน **Authorized redirect URIs**
5. นำ Client ID และ Client secret ไปใส่ใน Supabase secrets ตามตาราง
6. ระหว่างทดสอบ ให้เพิ่มบัญชี Google ที่จะใช้ทดลองเป็น **Test users**

สิทธิ์ที่แอปร้องขอคือ:

```text
https://www.googleapis.com/auth/calendar.readonly
```

สิทธิ์นี้ใช้สำหรับอ่านปฏิทิน รุ่นทดสอบยังอยู่ภายใต้ข้อจำกัด refresh token ของ Google ในโหมด Testing และเมื่อเปิดให้บุคคลทั่วไปใช้งานต้องดำเนินการเรื่อง consent/verification ตามข้อกำหนดของ Google ก่อน

เอกสารทางการ: [OAuth สำหรับเว็บเซิร์ฟเวอร์](https://developers.google.com/identity/protocols/oauth2/web-server), [สิทธิ์ของ Google Calendar](https://developers.google.com/workspace/calendar/api/auth)

## 5. ตั้งค่า Microsoft Outlook / Microsoft 365

ใน Microsoft Entra ให้ดำเนินการดังนี้:

1. ลงทะเบียนแอป โดยเลือกให้รองรับ **Accounts in any organizational directory and personal Microsoft accounts** เพื่อใช้ได้ทั้งบัญชีองค์กรและบัญชี Microsoft ส่วนตัว
2. เพิ่ม Redirect URI ชนิด **Web** โดยใช้ callback จากหัวข้อ 3
3. สร้าง client secret และเก็บค่า **Value** ไว้ใช้
4. ตั้งสิทธิ์ Microsoft Graph แบบ **Delegated permission** เป็น **Calendars.Read**
5. นำ Application (client) ID และ client secret Value ไปใส่ใน Supabase secrets

ระบบร้องขอ `offline_access` เพื่อให้ต่ออายุการเข้าถึงได้ และใช้ OAuth endpoint แบบ `/common`

บัญชีองค์กรบางแห่งอาจต้องให้ผู้ดูแลระบบอนุมัติตามนโยบายขององค์กร การเชื่อมต่อนี้รองรับปฏิทินบน Microsoft cloud ไม่ได้รองรับ Exchange server ที่องค์กรติดตั้งเองทุกแบบ

เอกสารทางการ: [ภาพรวม Outlook Calendar API](https://learn.microsoft.com/en-us/graph/outlook-calendar-concept-overview), [calendarView และนัดที่เกิดซ้ำ](https://learn.microsoft.com/en-us/graph/api/calendar-list-calendarview?view=graph-rest-1.0)

## 6. ตั้งค่า Apple Calendar / iCloud บน iPhone

โปรเจกต์ติดตั้ง `expo-calendar ~57.0.2` และเพิ่ม config plugin สำหรับข้อความขอสิทธิ์ไว้แล้ว ต้อง **build แอป iOS ใหม่** เพื่อให้มี native module ชื่อ `CalendarNext`

หากใช้ native project เดิม ให้ติดตั้ง dependencies ของ CocoaPods ที่เพิ่มเข้ามา และตรวจว่า Info.plist มีคีย์ต่อไปนี้:

```text
NSCalendarsUsageDescription
NSCalendarsFullAccessUsageDescription
```

Info.plist ของโปรเจกต์ iOS ที่สร้างไว้ใน workspace นี้ได้รับการปรับแล้วด้วย หากสร้าง native project ใหม่ config plugin ใน app config จะตั้งค่าข้อความเหล่านี้ให้

เมื่อใช้แอปที่ build ใหม่:

1. เปิด **Settings → Calendars** ใน VORA
2. กด **Connect Apple Calendar**
3. อนุญาตการเข้าถึงปฏิทิน
4. เลือกปฏิทินที่ต้องการอ่าน เช่น ปฏิทิน iCloud ส่วนตัว

iOS เรียกสิทธิ์นี้ว่า **Full Access** เพราะระบบไม่มีสิทธิ์แบบอ่านอย่างเดียวสำหรับข้อมูลปฏิทิน แต่โค้ด VORA เรียกใช้เฉพาะคำสั่งอ่าน และไม่ขอสิทธิ์เข้าถึง Reminders

ปุ่ม Apple Calendar แสดงเฉพาะบน iOS ไม่แสดงบนเว็บหรือ Android ฝั่งเว็บแยกโค้ดออกจาก native calendar module การเชื่อมแบบนี้อ่านผ่าน EventKit บนเครื่อง ไม่ใช่เซิร์ฟเวอร์ของ VORA เชื่อมกับ iCloud โดยตรง

เอกสารทางการ: [Expo Calendar สำหรับ SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/calendar/)

## 7. วิธีใช้งานหลังตั้งค่าเสร็จ

1. เข้าสู่ระบบ VORA หากจะใช้ Google หรือ Outlook
2. ไปที่ **Settings → Calendars** แล้วกด **Connect Google Calendar**, **Connect Outlook** หรือ **Connect Apple Calendar** บน iOS
3. อนุญาตสิทธิ์ แล้วเปิดสวิตช์เฉพาะปฏิทินที่ต้องการนำมาแสดง
4. เลือก **พื้นที่ส่วนตัว** และเปิดหน้า **Calendar** เพื่อตรวจนัด
5. ทดลองถามด้วยเสียง เช่น “พรุ่งนี้มีนัดอะไรบ้าง” หรือ “บ่ายวันศุกร์ว่างไหม”

ปุ่มที่ใช้จัดการการเชื่อมต่อ:

| ปุ่ม | การทำงาน |
| --- | --- |
| **Refresh calendars** | ดึงข้อมูลปฏิทินใหม่ด้วยตนเอง |
| **Reconnect** | เชื่อมบัญชีของผู้ให้บริการนั้นใหม่ และให้เลือกปฏิทินใหม่ |
| **Hide all connected calendars** | ยกเลิกการเลือกปฏิทินบนเครื่องและซ่อนนัดทั้งหมดทันที ใช้ได้แม้ติดต่อเซิร์ฟเวอร์ไม่ได้ |
| **Disconnect** | ตัดการเชื่อมต่อและยกเลิกการเลือกปฏิทินของผู้ให้บริการนั้น โดย Google/Microsoft จะลบ credentials และสถานะ OAuth ที่ค้างอยู่ฝั่งเซิร์ฟเวอร์ด้วย |

การกด Disconnect ไม่ได้ถอนสิทธิ์ที่เคยอนุญาตไว้ในบัญชี Google/Microsoft หากต้องการถอนสิทธิ์ด้วย ให้ลบ VORA ออกจากหน้าจัดการสิทธิ์แอปในบัญชีของผู้ให้บริการ ส่วนสิทธิ์ของ Apple จัดการผ่าน Settings ของ iPhone

## 8. พฤติกรรมและข้อจำกัดของรุ่นนี้

### การรีเฟรชและช่วงข้อมูล

ระบบรีเฟรชเมื่อเปิดหรือกลับเข้าแอป ทุก 5 นาทีขณะแอปทำงาน หลังเปลี่ยนปฏิทินที่เลือก และก่อนตอบคำถามเกี่ยวกับตารางหรือเวลาว่าง ผู้ใช้กดรีเฟรชเองได้ด้วย ยังไม่ใช่บริการ sync ฝั่งเซิร์ฟเวอร์ที่ทำงานต่อเนื่องเมื่อปิดแอป

ช่วงเริ่มต้นคือย้อนหลัง 30 วันและล่วงหน้า 180 วัน เมื่อเลือกวันจะโหลดช่วงข้อมูลรอบวันนั้น หากระบุช่วงวันที่ด้วยเสียง ระบบดึงข้อมูลตามช่วงที่ร้องขอ โดยบริการจำกัดช่วงต่อคำขอไว้ไม่เกิน 366 วัน

### การเก็บข้อมูลและกรณีเชื่อมต่อไม่ได้

ข้อมูลนัดภายนอกอยู่ในหน่วยความจำระหว่างใช้งาน ไม่บันทึกลง `items`, AsyncStorage, ระบบแชร์ในครอบครัว หรือระบบตั้งการแจ้งเตือนของ VORA มีเพียงการเลือกปฏิทินและค่าการเชื่อมต่อ Apple ที่เก็บไว้บนอุปกรณ์

เมื่อออฟไลน์หรือดึงข้อมูลไม่สำเร็จ ระบบล้างข้อมูลนัดภายนอกที่โหลดไว้ และแจ้งว่าตอบคำถามตาราง/เวลาว่างไม่ได้ แทนการสรุปว่า “ว่าง” จากข้อมูลที่ไม่ครบ

### การเก็บ token

OAuth token เก็บแบบเข้ารหัสในตารางที่เข้าถึงได้เฉพาะ `service_role` สถานะการเชื่อมต่อใช้ค่าสุ่ม เก็บเป็น SHA-256 ใช้ PKCE มีอายุ 10 นาที และบันทึกผลพร้อมใช้สถานะนั้นให้หมดสิทธิ์ในธุรกรรมเดียวกัน

URL ที่ส่งผู้ใช้กลับเข้าแอปไม่มี access token หรือ refresh token ของผู้ให้บริการ และ URL สำหรับโหลดข้อมูลหน้าถัดไปถูกจำกัดให้เป็น HTTPS API ของผู้ให้บริการนั้น

### นัดซ้ำ นัดทั้งวัน และเขตเวลา

Google ใช้ `singleEvents` เพื่อแยกนัดที่เกิดซ้ำเป็นแต่ละครั้ง Outlook ใช้ `calendarView` และ Apple อ่านแต่ละครั้งผ่าน EventKit การรีเฟรชสำเร็จจะนำข้อมูลช่วงใหม่มาแทนช่วงเดิม จึงสะท้อนนัดที่ถูกลบหรือยกเลิกด้วย

วันสิ้นสุดของนัดทั้งวันไม่นับรวมเป็นวันนัด เช่น ช่วง 7–9 กันยายนแบบวันสิ้นสุดไม่รวม หมายถึงนัดวันที่ 7 และ 8 กันยายน นัดที่มีเวลาแสดงตามเขตเวลา Bangkok ที่ VORA ใช้อยู่ ส่วนวันที่ของนัดทั้งวันคงตามปฏิทินต้นทาง

### การป้องกันรายการซ้ำ

ระบบรวมรายการซ้ำเฉพาะเมื่อ **iCalendar UID จากต้นทางและช่วงเวลาของนัดครั้งนั้นตรงกัน** ชื่อและเวลาตรงกันอย่างเดียวจะไม่ทำให้รายการถูกซ่อน เพราะอาจเป็นคนละนัด

Expo ยังไม่ส่งรหัสสากลที่ใช้เทียบกันได้สำหรับนัด Apple ดังนั้นถ้าบัญชี Google/Outlook เดียวกัน sync อยู่ใน iPhone ด้วย ให้เลือกอ่านปฏิทินนั้น **ผ่านการเชื่อมตรงหรือผ่าน iPhone เพียงทางเดียว** เพื่อป้องกันรายการซ้ำ มีข้อความอธิบายเรื่องนี้ในหน้าตั้งค่าแล้ว

### การหาเวลาว่างและจำนวนปฏิทิน

นัดที่ตั้งสถานะเป็น **Free** ยังแสดงอยู่ แต่ไม่กันช่วงเวลานั้นออกจากผลการหาเวลาว่าง นัดที่ยกเลิกและคำเชิญที่ปฏิเสธใน Google/Outlook จะถูกตัดออก ส่วน Apple ใช้สถานะเวลาว่างจาก EventKit และยังไม่ได้กรองตามคำตอบรับคำเชิญของผู้เข้าร่วมแต่ละคน

เลือกได้สูงสุด 30 ปฏิทินต่อผู้ให้บริการในหนึ่งคำขอ ระบบจำกัดจำนวนหน้าข้อมูลและจำนวนนัดที่โหลด และจะไม่รายงานผลที่โหลดได้เพียงบางส่วนว่าเป็นข้อมูลครบถ้วน

## 9. ตรวจสอบและทดสอบก่อนใช้งานจริง

รันจากโฟลเดอร์โปรเจกต์:

```sh
npm run test:calendar
npm run test:calendar-api
npx tsc --noEmit
deno check supabase/functions/calendar-api/index.ts
npm run web:build
```

คำสั่ง `deno check` ต้องมี Deno ติดตั้งอยู่ในเครื่อง

**`test:calendar`** ทดสอบโค้ดแปลงข้อมูลและ store จริง โดยจำลองผู้ให้บริการและที่เก็บข้อมูล ครอบคลุมขอบเขตนัดทั้งวัน นัดยกเลิก/ปฏิเสธ เวลาว่าง/ไม่ว่าง การรวมรายการซ้ำของนัดแต่ละครั้ง การเลือกปฏิทินก่อนนำเข้า การแยกบัญชี/พื้นที่ ผลตอบกลับที่มาช้า การตัดการเชื่อมต่อ ข้อผิดพลาด และการใช้ Apple ขณะบริการ cloud ไม่พร้อม

**`test:calendar-api`** ทดสอบ Edge handler จริง โดยจำลองฐานข้อมูลและผู้ให้บริการในหน่วยความจำ ครอบคลุมการตรวจ JWT การจำกัดข้อมูลตามเจ้าของ URL ที่อนุญาต PKCE การป้องกันนำ OAuth state กลับมาใช้ซ้ำ การเข้ารหัส credentials สิทธิ์เลือกปฏิทิน ขีดจำกัดการโหลดหน้าข้อมูล และการตัดการเชื่อมต่อ เทสต์นี้ไม่ได้ตรวจสิทธิ์ฐานข้อมูลที่ deploy จริง หรือทดลอง OAuth กับ Google/Microsoft จริง

หลังตั้งค่าและ deploy แล้ว ให้ทดสอบกับบัญชีจริงตามลำดับ:

1. เชื่อมบัญชี Google และ Microsoft สำหรับทดสอบ แล้วเลือกปฏิทินอย่างน้อยหนึ่งรายการ
2. ตรวจว่ามีนัดปกติ นัดที่เกิดซ้ำ และนัดทั้งวันแสดงถูกต้อง
3. ย้ายเวลาและยกเลิกนัดในแอปต้นทาง จากนั้นรีเฟรช VORA และตรวจว่าข้อมูลเปลี่ยนตาม
4. ถามด้วยเสียงเกี่ยวกับวันนัดและเวลาว่าง
5. กด Disconnect แล้วตรวจว่านัดหายจาก VORA
6. สลับผู้ใช้ VORA แล้วตรวจว่าไม่เห็นนัดของบัญชีก่อนหน้า
7. บน iPhone จริงที่ build แอปใหม่แล้ว ทดสอบการอนุญาต ปฏิเสธ และถอนสิทธิ์ปฏิทิน รวมถึงนัดจาก iCloud

การผ่านเทสต์อัตโนมัติและ build เว็บไม่ได้ทดแทนการทดสอบกับบัญชีผู้ให้บริการและอุปกรณ์จริงเหล่านี้
