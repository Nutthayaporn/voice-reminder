# Test corpus — "ภาษา" ของแอป (ประโยคจริงสำหรับทดสอบ routing)

รวมประโยคตัวอย่างครอบคลุมทุกความสามารถของสมอง ใช้จูน prompt + จับ intent ที่หลุด
ตามที่ ChatGPT แนะให้ "ออกแบบภาษา 50–100 ประโยคก่อนเขียน UI".

รันทีละประโยค:
```bash
node scripts/test-brain.mjs "พรุ่งนี้เตือนกินยา 9 โมง"
```

เครื่องหมาย: ✅ รองรับแล้ว · ⚠️ ยังไม่รองรับ (ดูหมายเหตุท้ายไฟล์)

---

## A. Reminder — ครั้งเดียว (เวลา/วันหลากหลาย) ✅
- พรุ่งนี้อย่าลืมกินยาตอน 9 โมง
- เตือนประชุมบ่าย 2 โมงครึ่ง
- มะรืนนี้ตี 5 ปลุกไปสนามบิน
- เตือนโทรหาหมอวันศุกร์หน้า 10 โมงเช้า
- วันที่ 15 จ่ายค่าบัตรเครดิต
- คืนนี้เที่ยงคืนเตือนดูบอล
- สิ้นเดือนนี้เตือนโอนค่าหอ

## B. Reminder — ซ้ำ (recurring) ✅
- ตั้งปลุกทุกวัน 8 โมง ยกเว้นเสาร์อาทิตย์      # weekly MO–FR
- เตือนกินวิตามินทุกวัน 8 โมงเช้า              # daily
- ทุกวันจันทร์เตือนประชุมทีม 10 โมง            # weekly เฉพาะ MO
- ทุกวันที่ 1 เตือนจ่ายค่าเช่า                  # monthly
- ทุกปีวันที่ 5 พฤษภา เตือนวันเกิดแม่           # yearly
- เตือนรดน้ำต้นไม้วันเว้นวัน                    # interval (อาจตีความยาก—ดูผล)

## C. Reminder — เวลาสัมพัทธ์ (relative) ✅
- อีกครึ่งชั่วโมงเตือนปิดเตา
- อีก 2 ชั่วโมงเตือนออกไปรับลูก
- อีก 15 นาทีเตือนโทรกลับลูกค้า

## D. Event / นัด (เดี่ยว + ช่วง + พ่วง reminder = multi-action) ✅
- วันที่ 1 ถึง 2 กันยา พ่อแม่ไปขายของ           # ช่วงวัน
- ศุกร์นี้มีนัดหมอฟันบ่าย 3                      # เดี่ยว มีเวลา
- 1–2 กันยา พ่อแม่ไปขายของ เตือนผมก่อนหนึ่งวันด้วย   # event + reminder
- วันเสาร์ไปงานแต่งเพื่อน เตือนเช้าวันนั้นด้วย

## E. Todo — งานที่ต้องทำ (ไม่มีเวลา / มี reminder) ✅
- ต้องซื้ออาหารแมว
- อย่าลืมโทรนัดช่างแอร์
- เย็นนี้เตือนซื้อไข่ด้วย                        # todo + reminder
- ไว้ต้องไปต่อภาษีรถ

## F. Note / Diary (milestone / ธรรมดา / มีคน) ✅
- วันนี้เป็นวันแรกที่ลูกพูดได้                    # milestone + people
- วันนี้ลูกเดินได้เอง 3 ก้าวแล้ว
- วันนี้เหนื่อยมาก งานเยอะ                       # diary ธรรมดา
- เมื่อวานไปกินร้านใหม่กับแฟน อร่อยมาก

## G. Expense (พื้นฐาน / ร้าน / ย้อนหลัง / รายรับ) ✅ (รายรับดูหมายเหตุ)
- ซื้อโจ๊กไป 60 บาท
- จ่าย Starbucks 180
- เมื่อวานจ่ายค่าข้าว 120                         # backdate
- เติมน้ำมัน 500 บาท
- ได้เงินเดือน 30000                             # ⚠️ รายรับ (ปัจจุบันมองเป็น expense)

## H. Query — ตาราง (วันนี้ / พรุ่งนี้ / ช่วง) ✅
- วันนี้มีอะไรต้องทำบ้าง                          # list_today
- พรุ่งนี้มีนัดอะไรไหม                            # list_range (พรุ่งนี้)
- อาทิตย์นี้มีอะไรบ้าง                            # list_range (สัปดาห์นี้)

## I. Query — ค้นความทรงจำ (semantic recall) ✅
- ลูกเริ่มพูดได้ตั้งแต่เมื่อไหร่
- ครั้งล่าสุดที่ไปเที่ยวทะเลเมื่อไหร่
- ปีนี้ลูกมี milestone อะไรบ้าง

## J. Query — งบประมาณ (ถามยอดใช้จ่าย) ⚠️ ยังไม่รองรับ
- เดือนนี้ใช้เงินไปเท่าไหร่แล้ว
- เหลืองบกินข้าวเท่าไหร่

## K. Query — วันหยุด ⚠️ ยังไม่รองรับ (ตัวอย่างเดิมของเจ้าของ)
- เดือนนี้มีวันหยุดไหม

## L. Update / เลื่อน / แก้ (multi-turn — ต้องมีรายการอ้างอิงก่อน) ✅
- เลื่อนอันแรกไป 11 โมง
- เปลี่ยนนัดหมอเป็นบ่าย 2
- อันเมื่อกี้เลื่อนไปพรุ่งนี้

## M. Delete / ยกเลิก ✅
- ยกเลิกนัดหมอ
- ลบอันเมื่อกี้
- ไม่เอาการเตือนกินยาแล้ว

## N. ทำเครื่องหมายเสร็จ (complete todo) ✅
- จ่ายเน็ตแล้ว
- ซื้อไข่แล้ว
- ทำเสร็จหมดแล้ว

## O. Confirmation — เวลากว้าง ต้องถามกลับ ✅
- เตือนกินยาพรุ่งนี้เช้า                          # → "กี่โมงครับ"
- เตือนโทรหาแม่เย็นนี้                            # → "กี่โมงครับ"
- (เทิร์นถัดไป) 8 โมง                             # เติมให้ครบ

## P. Multi-action (หลายคำสั่งในประโยคเดียว) ✅
- พรุ่งนี้ประชุม 10 โมง แล้วก็เตือนซื้อของขวัญด้วย
- จองหมอฟันศุกร์นี้ แล้วก็บันทึกว่าฟันปวดมา 3 วันแล้ว

## Q. Chit-chat / กำกวม / ปฏิเสธ (ควร no-op หรือถาม) ✅
- สวัสดีตอนเช้า
- เป็นไงบ้างวันนี้
- เอ่อ... เดี๋ยวนะ

## หมายเหตุ (ช่องว่างที่รู้ตัว)

- **⚠️ J. งบประมาณ**: ตอนนี้ `record_expense` เขียนอย่างเดียว (deep link ไป daily-budget)
  ยังถาม "ใช้ไปเท่าไหร่/เหลือเท่าไหร่" กลับไม่ได้ — ต้องมี budget-read API ก่อน (Phase ต่อไป)
- **⚠️ K. วันหยุด**: ตัดตาราง holidays ออกตั้งแต่แรก — ตอบได้เฉพาะถ้าผู้ใช้เคยจดวันหยุดเป็น item
  ถ้าอยากได้จริง ต้องเสียบปฏิทินวันหยุดไทย (seed/API)
- **✅ H. ช่วงเวลา (พรุ่งนี้/อาทิตย์นี้)**: รองรับแล้ว — สมองเติมช่วงวัน (`list_range`
  datetime→end_datetime), `queryItems`/`itemsInRange` กรองตามช่วง (honor recurring, dedupe)
- **⚠️ G. รายรับ**: schema มีแต่ expense — "ได้เงินเดือน" ปัจจุบันกลายเป็น note ถ้าต้องแยก
  ต้องเพิ่ม type income
- **C/B interval**: "วันเว้นวัน" / relative time อาจตีความพลาดได้ ควรเทสต์จริง
